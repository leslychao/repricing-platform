# Repricer

Платформа управления ценами Ozon и Яндекс Маркета. Требования и границы находятся в [спецификации](docs/Repricer_Specification.html), интерфейс — в [дизайне v19](docs/Repricer-Final-v19.html).

Код: `backend/` — Java 21 и шесть Maven-модулей; `frontend/` — Angular 22. `api` и `worker` используют один образ. Браузер обращается только к Nginx приложения; PostgreSQL, Redis, Vault, SeaweedFS и Mailpit не публикуют порты хоста. Redis хранит только сессии входа. Рабочие данные PostgreSQL, Vault, S3 и Mailpit сохраняются в именованных томах.

## Local

Требуются Docker с Compose и Linux shell. Скопируйте `deploy/.env.local.example` в `deploy/.env.local`, задайте все пустые секреты. `OAUTH2_COOKIE_SECRET` — base64 от 32 случайных байтов. Остальные секреты задаются независимо; их нельзя коммитить. Не экспортируйте одноимённые параметры в запускающем процессе: Compose отдаёт им приоритет над выбранным env-файлом.

```sh
docker compose --env-file deploy/.env.local -f deploy/docker-compose.yml config --quiet
docker compose --env-file deploy/.env.local -f deploy/docker-compose.yml up --build --detach --wait --wait-timeout 300
```

Вход: адрес `PUBLIC_BASE_URL` из выбранного env-файла. `test` и `admin` получают пароли из `KEYCLOAK_TEST_PASSWORD` и `KEYCLOAK_APP_ADMIN_PASSWORD`. Это пользователи приложения, не администраторы Keycloak. Отдельный bootstrap-администратор задан `KC_BOOTSTRAP_ADMIN_USERNAME/PASSWORD`. Повторная подготовка изменяет только помеченные управляемые записи с ожидаемыми ID; конфликт с чужой записью останавливает запуск.

Форма входа — собственная тема Keycloak с оформлением v19. OAuth2 Proxy выполняет Code/PKCE S256 и хранит сессии в Redis; frontend не получает токены. Выход согласует завершение SSO и очистку сессии прокси. Временная ошибка выхода не считается успехом.

Vault использует постоянный Raft storage. Материал начальной инициализации хранится в закрытом томе `vault-bootstrap`; entrypoint штатно снимает seal после перезапуска. В API и worker монтируется только файл ограниченного токена. Это конфигурация local/dev; root token не передаётся приложению. При утрате рабочего тома старые данные не воссоздаются.

Mailpit принимает письма только внутри Compose, реальным адресатам их не отправляет. Его UI привязан к loopback контейнера и не опубликован. Технический просмотр возможен через закрытый Docker-канал, например `docker compose ... exec mailpit wget -qO- http://127.0.0.1:8025/api/v1/messages`.

## Dev

Скопируйте `deploy/.env.dev.example` в `deploy/.env.dev`, задайте собственные секреты и фактические параметры входа. `DEV_HOST` указывает сервер Docker, `GLOBAL_NGINX_HOST` — независимо управляемый инфраструктурный Nginx. `TRUSTED_PROXY_CIDR` и `GATEWAY_ALLOWED_CIDR` должны разрешать его реальный источник; `GATEWAY_BIND` и `GATEWAY_PORT` определяют внутренний вход приложения. `DOCKER_AUTH_CIDR` — свободная подсеть Docker для аутентификации.

```sh
bash deploy/deploy-dev.sh deploy/.env.dev deploy/docker-compose.yml
```

Скрипт проверяет конфигурацию, собирает образы на Docker-хосте через закрытый TCP 2375 и выполняет Compose с проверкой готовности. Применяемые конфигурации входят в образы: bind mounts файлов локального checkout на удалённый сервер отсутствуют. Обычный повторный запуск сохраняет тома и realm. Изменение dev-сервера требует изменения env-файла, а не скрипта.

Публичный домен и адрес глобального Nginx не предоставлены. До их настройки и подготовки сертификата публичный маршрут не готов. Скрипт не изменяет глобальный Nginx, Docker daemon и сертификаты. Разбор Compose и healthcheck не заменяют браузерный вход, выход и работу через оба прокси.

Конфигурация IDEA `Deploy dev` вызывает тот же shell-скрипт через установленную WSL. Все пути построены от `$PROJECT_DIR$`, включая путь с пробелами. В WSL должны быть доступны Docker CLI и Compose. Запуск после переноса checkout проверяется отдельно в IDEA.

## Проверки приложения

```sh
cd backend
./mvnw -B -ntp verify
cd ../frontend
npm ci
npm run build
```

Интеграционные проверки требуют доступного Docker. Все образы закреплены точными registry digest; зависимости — штатными Maven/npm-файлами. Проверки внешних возможностей выполняются отдельно для конкретного кабинета. Непроверенный профиль записи остаётся закрытым.

Резервное копирование и восстановление из резервных копий исключены из этой поставки. Постоянное хранение, возобновление текущих заданий, операционный журнал отправок и сверка UNKNOWN остаются частью обычной работы. Команды, удаляющие тома, не входят в деплой.
